## 为什么这道题要用并查集？

这道题的核心是：**给定一些允许交换的下标对，经过任意次交换后，source 数组中哪些位置上的元素可以互换位置？**

关键在于：交换关系具有**传递性**。  
例如，如果允许交换 (0,1) 和 (1,2)，那么 0 和 2 也能通过 0↔1↔2 间接交换，最终 0、1、2 三个位置上的元素可以任意排列。  
这本质上就是**图论中的连通分量**——每个连通分量内的所有下标可以任意重排其中的元素。

因此，问题转化为：

1. 将所有可互换的下标（通过直接或间接的交换）合并成若干个**连通块**。
2. 在每个连通块内部，source 中的元素可以任意排列去匹配 target。
3. 最小汉明距离 = 每个连通块内无法匹配的元素数量总和。

**为什么用并查集？**  
并查集（Union-Find）正是专门用来**动态维护元素之间的连通性**、**快速合并集合**和**查询元素所属集合**的数据结构。  
它能在近乎 O(1) 的时间内完成合并和查找操作，非常适合本题：  
- 遍历 allowedSwaps，对每一对 (a,b) 执行 `union(a,b)`，就能将所有间接连通的点归入同一集合。  
- 然后只需对每个下标执行 `find(i)` 就能知道它属于哪个连通块，进而统计每个块内的元素频率。

如果不用并查集，就需要用 DFS/BFS 建图，每次查询下标归属都要遍历整个图，效率低很多（尤其是当 allowedSwaps 很多时）。并查集通过**路径压缩**和**按秩合并**，几乎达到了常数时间。

## 使用并查集的题目有哪些共同特点？

并查集特别适合解决以下几类问题，你可以根据这些特征快速判断：

### ✅ 1. 元素之间存在**传递性**的关系
- 例如：A 与 B 相连，B 与 C 相连 ⇒ A 与 C 相连（连通性）
- 例如：A 与 B 相等，B 与 C 相等 ⇒ A 与 C 相等（等式关系）
- 例如：A 与 B 可交换，B 与 C 可交换 ⇒ A 与 C 可交换（交换关系）

### ✅ 2. 需要**动态合并集合**，并**查询元素所属集合**
- 题目会先给你一些“合并指令”（如边、交换对、相等关系）。
- 然后需要快速知道某个元素属于哪个组，或者两个元素是否在同一个组。
- 并查集的 `union` 和 `find` 正是为此而生。

### ✅ 3. 问题可转化为**处理每个连通分量（等价类）**
- 一旦元素被分组，通常会对每个组进行统一操作：
  - 统计组内元素的某种属性（如频率、最小值、最大值）。
  - 组内元素可以自由排列（如交换字符串、重排数组）。
  - 判断组内是否满足某种条件（如无环、无矛盾）。

### ✅ 4. 通常**不关心具体的连接路径**，只关心最终的连通状态
- 比如，你不需要知道 0 和 2 是通过哪条路径连起来的，只需要知道它们是否连通。
- 并查集“压缩路径”后，直接告诉根节点，隐藏中间细节。

### ✅ 5. 常见关键词
- **连通分量** / **省份** / **朋友圈**
- **可交换** / **可互换** / **允许交换**
- **相等关系** / **不等关系**（配合“==”和“!=”）
- **冗余连接**（判断加一条边后是否会成环）
- **最小生成树**（Kruskal 算法中判断是否连通）

## 总结

**为什么用并查集？**  
因为它能以近乎 O(1) 的复杂度处理元素的分组合并和归属查询，完美契合“交换关系具有传递性”这一特点。

**用并查集的题目特点**：  
- 存在**传递性关系**（连通、相等、可交换等）。  
- 需要**动态合并集合**并**频繁查询**元素所属集合。  
- 问题最终归结为**对每个连通分量独立处理**。

掌握了这些特征，下次看到“可交换”、“连通”、“等价”等关键词，你就能迅速想到并查集了。
